# 2026-08-24 — #16 root cause; undiscovered-node detection validated

Point-in-time record. The living account is `CONTINUATION.md` (§4a–§4d, §6c); the
handoff is `CONTINUATION-PROMPT.md`; evidence and re-runnable tooling are under
`findings/2026-08-24-*/`.

## One-paragraph summary

The scanner's recall bug was root-caused: pass 1 finds 100% of known nodes, pass 2
resolves 2.8%, and the reason is that ore nodes are **384-byte spawn records, not
actors** — nothing in memory points at them, so the `actor → RootComponent` chain the
tool is built on cannot reach them. A signature-based census replaces it and hits
**64.3% on DeepDesert, 58.5% on Hagga, in 17 seconds**. It was then validated as finding
**genuinely undiscovered** nodes (60.2% of markers discovered *after* the scan). Two real
code defects were fixed, three published claims were corrected — one of mine, one of the
project's, one from another developer — and **resource type attribution remains
unsolved**, which is now the only thing between here and a labelled post-storm map.

## What was established

### #16 root cause

- Ground truth: 211 markers in the WindPass box. Pass 1 **211/211 (100%)**; pass 2
  **6/211 (2.8%)**. The 96 actors the old scanner returns occupy only 42 distinct
  positions.
- The hypothesis #16 was opened with is **disproved**: offset-agnostically, nothing points
  into the 2 KB preceding these transforms, so widening the region set cannot help.
- A memory dump showed the real shape: repeating **384-byte spawn records** with a
  pre-trace and a terrain-snapped position triple 24 bytes apart.
- Signature-filtering gives **64.3% DD / 58.5% Hagga**, 17 s, 136 MB RSS — against the
  shipped scanner's 2–5 minutes on a *single box* and 12.6 GB peak.

### Validation that it finds *undiscovered* nodes

- **Retrospective**: 60.2% of the 1,667 markers discovered *after* the census was captured,
  vs 64.8% of already-known ones. Statistically the same. **Discovery is not required** —
  this is the post-storm capability, demonstrated rather than assumed.
- **Cross-map**: the DeepDesert-derived signature applied unchanged to HaggaBasin —
  different map, authored terrain, restarted process, fresh ASLR — gives 58.5% with the
  same per-type structure. Map- and process-independent.

### POIs need no scanner

Every POI marker on both maps is `long_range=true` and named (Cave, Ecolab, Shipwreck,
TaxiService, Sietch — 100% of rows; only `NoIcon` is neither). They are revealed at range,
so the DB already holds them all. This refines §5's blanket "never an exhaustive atlas"
warning, which stays correct only for resource nodes, and confirms the census's 0% POI
coverage as expected per §5c.

### Type attribution — four routes ruled out

Actor chain; all 48 record offsets (`+0` is unique per record, zero collisions); the object
`+0` points at (a bounding box, not a UObject); memory-address clustering (30.9% vs a 12.9%
chance baseline). **The type does not live in the record, in what it points at, or in its
placement.**

## Defects fixed

- **#18 (new)** — `FindNearbyXY` accepted NaN pairs: both guards were negations and every
  NaN comparison is false, so 16 bytes of `0xFF` matched *any* target at *any* tolerance.
  17.4M of 17.4M hits. After: 623k hits, coverage unchanged, RSS 12.6 GB → 165 MB.
- **#14** — `ValidTransform` denormal / `Inf` / unbounded-Z guards.
- **census junk filter** — 1,709 records (2.0%) sat near the world origin. Fixed via
  `ValidTransform` plus a **radial** origin test; the per-axis version written first would
  have discarded up to 98 real nodes, because DD crosses the origin.

## Three corrections issued

- **Mine.** I published that the 80,803 unmatched census records were "NOT all undiscovered
  nodes", citing a Z gap of 18,058 vs 3,715. **Largely wrong** — mostly exploration bias
  (4,701 in explored cells vs 19,317 elsewhere; controlled, 3,559 vs 7,060). A structural
  signature from the 5,899 confirmed nodes passes 96.4% of all records, so there is no
  node/non-node signal at all.
- **The project's.** §6c claimed `dune admin teleport` works with a delay. Re-tested three
  ways — two long-range, one 3,000 uu hop inside loaded terrain — all `publish=ok`, exit 0,
  **zero movement**. The original "accepted but never moves" finding was right. An operator
  flying is indistinguishable from a teleport if position is sampled only before and after.
- **Another developer's.** Reported that the `field_id` decode "fails only past
  ±1,048,575". The **premise is correct and was not recorded anywhere** — 1,237 of 9,601 DD
  markers (12.9%) lie beyond the 21-bit limit, so the spice layer is only proven for the
  inner ~87% of the map. The **conclusion did not reproduce**: none of the 19 observed
  misses is near the limit (largest 803,675), the most extreme value in the set (1,044,975)
  decodes correctly, un-aliasing rescues none, and matched/missed rows have
  indistinguishable decoded-Z distributions — so the decode works and those fields are
  absent from the memory scan, which points back at #16.

## Process notes worth carrying forward

- **A local `timeout ssh` does not kill the remote process, and a wall-clock timeout does
  not bound memory.** Two diagnostics had to be killed by hand; one reached 10.7 GB RSS on
  a host with 24 GB free that also runs the live game server. Game PIDs and free memory
  were re-verified afterwards each time; no OOM occurred. `census.go` now streams to disk
  and takes `-maxrecords`.
- **A scoring metric can look like a result.** The first type-discriminator search reported
  a confident `pure = 15` that was an artifact of `0x0` satisfying "every marker of this
  type shares a value". Both the wrong and corrected runs are kept in `findings/`, because
  the wrong output is plausible enough to mislead the next reader.
- **Check a filter against real data before shipping it.** The per-axis origin filter looked
  obviously correct and would have silently dropped real nodes.
- **Operator pushback caught a real gap.** I began writing the instance dependency up as
  settled; it is not. Every scan ran while a session was registered `Online` on
  `DeepDesert_1`, even while the operator was not playing.

Deep Desert Scanner Findings

What has been established about reading resource-node positions from a live Dune: Awakening server, what has been disproved, and what remains open. Every claim here is measured against the game database as ground truth.

The practical summary. Immediately after a Coriolis storm you could publish spice by tier, flour sand, player bases, points of interest, and an unlabelled “a resource node is here” layer. You could not yet say which node is Titanium and which is a bush.

Findings

Ore nodes are not actors — root cause of the recall defect

  • EstablishedThe position search locates 211 of 211 known markers. Resolving those to actors yields 6 of 211. The loss is entirely in resolution, not search.
  • DisprovedThe original hypothesis — that back-references lay outside the scanned memory regions. Searched without assuming any offset, nothing in memory points into the 2 KB preceding these nodes.
  • EstablishedOre, scrap and pickup nodes are 384-byte spawn records, not engine actors. Spice and flour sand are unaffected, which is why that path always worked.
  • DisprovedType attribution via the record fields, the object it references, or memory placement. All four routes ruled out against 2,931 unambiguously labelled records.

The scanner finds nodes nobody has discovered

The decisive test, and it needed nobody in game. The marker table grew while the map was explored; anything discovered after a scan was captured is a blind test the scanner could not have known about.

Statistically the same rate. The remaining gap is type mix, not capability. Applied unchanged to the second map — authored terrain, a different process that had restarted — it holds at 58.5% against 64.3%, so the method is independent of map and of process.

The coordinate packing cannot describe the whole map

  • BoundedThree 21-bit signed fields give a range of ±1,048,575. Deep Desert reaches roughly ±1.27M, so 12.9% of real markers cannot be encoded at all. The spare 64th bit is unused, so there is no escape mechanism.
  • DisprovedAn external report attributing decode failures to this overflow. None of the 19 observed failures is near the limit; the most extreme in-range value decodes correctly; and reversing the wrap rescues none of them.
  • EstablishedThose failures are a scanner under-count, not a decode error — failed and successful rows have indistinguishable decoded elevation distributions, which a broken decode could not produce.

Why this still matters. An out-of-range coordinate does not fail loudly — it wraps to a plausible-looking value of the opposite sign. Silently wrong is worse than missing, so consumers should range-check rather than trust the decode.

External document reviewed — the “marker atlas”

A third-party description of the database schema, checked claim by claim. The structure is sound; the framing is not.

  • AccurateAll 26 named point-of-interest, vendor, trainer and faction types exist. The example queries work. Resource-kind semantics and all three spice tier values are correct.
  • InaccurateThe marker composite type has five fields, not the four described, and the first is named differently — code written to the stated definition fails outright.
  • InaccurateThe partition table holds 30 maps, not 39. The claimed “devoured by a sandworm” event type does not exist, and the document's own query for it returns nothing.
  • Not checkableEvery per-type count, including the headline total. These are not errors — see below.

The counts looked contradictory at first: some five to twelve times ours, others barely half. That is fully explained once split by map. One map is authored and never resets, so discoveries accumulate indefinitely; the other is regenerated by every Coriolis storm, so its counts belong to whichever seed is live.

Corrections issued

Recorded deliberately — a finding that quietly replaces an earlier one leaves the next reader unable to tell which was checked.

  • RetractedA claim that unmatched scan records were mostly not real nodes. The elevation gap cited turned out to be exploration bias — explored ground is simply lower — and a structural test then passed 96.4% of all records as indistinguishable from confirmed nodes.
  • RetractedA prior session's note that the administrative teleport command works with a delay. Re-tested three ways, including a short hop inside already-loaded terrain: accepted every time, and the character never moved.
  • QualifiedAn external count discrepancy first read as internally inconsistent. The operator identified the cause — a far larger, busier server — and the per-map split confirmed it.
